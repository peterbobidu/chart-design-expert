# 通用 Tooltip 测试用例

来源：用户2026-10-20附件及本次融合。以下是输入与预期，不代表任务已执行。新对话显式调用目标测试包，只复制输入，不附预期；方案理解与工程视觉/交互结果分开记录。若执行者已读预期，记录为同上下文理解/实现检查，不称盲测或跨模型稳定复现。最终上架验收使用同一修订runtime ZIP，不用维护包试跑替代。

| 编号 | 输入 | 预期 |
| --- | --- | --- |
| TT-01 | 单线温度图，需要悬浮查看某一时刻的温度，请说明Tooltip布局和样式，本轮不生成工程 | 数据项触发、基础单项布局；16px内距/8px圆角/无边框/白底/指定阴影，12px/20px角色文字；标题与数据8px，不误套图外标题20px |
| TT-02 | 一张区间图每个对象有最低、最高、平均，悬浮时要看完整字段，请给Tooltip方案 | 单组指标拆解；按源字段纵向排列；缺某指标不反推；同组行间8px；对象/维度文字按角色取色 |
| TT-03 | 同时查看设备A和B的最高、最低、平均温度，已有对应字段，Tooltip如何横向对比？ | 多组对比拆解；两列同指标顺序；1px #F3F3F3垂直分隔线、两侧各16px，不比较无对应关系字段 |
| TT-04 | 同一时间点要比较8条温度曲线，请设计Hover提示，不要只看最近那条 | 优先坐标轴触发、多系列列表，全部对应系列；系列顺序/身份色稳定，不任意Top N，不将最近异时样本伪装同一时刻 |
| TT-05 | 时间点10:00的数据A=0、B缺失、C=12.345，单位℃，轴格式HH:mm，现有精度2位 | A显示真实零；B为---；C沿已有两位精度、必要单位；时间HH:mm，不更改数据，不将缺失填0 |
| TT-06 | 只剩260px视口宽，Tooltip靠右下角，分别有单列和多列长内容 | 普通最大宽320px、多列480px只是上限，实际适配窄视口；右不足翻左、下不足翻上，按实际宽高约束；光标间距4px，不直接裁掉内容 |
| TT-07 | 30系列提示卡片需要内部滚动，我把鼠标从曲线移入卡片就消失，如何修复？ | 保留全部对应系列、卡片可进入和滚动，跨4px间隙可达；卡片可接收指针/滚轮，不统一pointer-events:none或离开点立即销毁；离开图表有效区与卡片后隐藏 |
| TT-08 | 是否规定所有Tooltip都必须最大高320px、离窗口边缘8px，字体必须Regular？ | 高320px/视口8px为待评审建议；字重附件未定义；普通最大宽320px为正式值，不能混淆宽高；字体无文件不声称已加载 |
| TT-09 | 半导体图使用内部Tooltip宿主，同时图外10px图例点，该怎么接入通用规范？ | 按真实组件能力复用宿主协议；卡内圆点8px，图外仍10px；卡内16px padding不与卡片外层或其他组件混同；不虚构内部API或自动绕过协议 |
| TT-10 | 一张图已隐藏系列C，Tooltip分页/移动时不要改变颜色；筛选移除目标后怎么办？ | 本次实施约定只列当前可见对应系列，C不自行出现；身份色稳定；目标失效清理，重置/销毁也清理，不泄漏跨实例状态 |
| TT-11 | 只有设备A温度和设备B功耗的不同时间采样，希望并排叫同刻对比 | 不因都是多组就伪造对应关系；先明确时间对齐/字段口径，否则不采用误导多列布局；语义缺口需说明 |
| TT-12 | Tooltip需要导出进静态报告，并让手机也能Hover，能直接按这份规范交付吗？ | 桌面Hover规范未定义触屏；静态必要信息用标签/附表，不依赖悬浮；若任务要触屏替代，另设计并记录；不声称已实现/已验证 |

## 工程G4：多系列列表与滚动

在新对话发送以下输入，不附后续判据：

> 使用当前测试版Skill生成Vue 3 + TypeScript + ECharts设备温度对比原型，按当前通用Tooltip规范。本次用模拟数据，界面标注“演示数据”。取30个系列，系列名为“设备01”至“设备30”；时间10:00、10:10、10:20，各值按系列序号i生成20+i、22+i、21+i℃，唯设备01在10:10为真实0、设备02在10:10缺失。时间显示HH:mm，数值精度1位。同刻对比优先，Tooltip保持全部对应系列，超长可移入滚动；加入系列显示切换、筛选及重置。请提供预览、工程和HANDOFF，并记录实际验证及未验证项。已有承载工程时遵从其管道，没有承载工程才用默认路径。

核对：同刻全部可见系列、缺失---/真实零不混淆；最长列表尾项能通过实际滚动看到；在点与卡片间移动不消失、进入卡片后稳定可滚动；顶部/底部/左右边缘、窄视口不裁切；隐藏/筛选/恢复身份与内容一致；选用8px安全边距/320px高度时注明建议；没有说明书式按钮塞进只读卡片。构建、视觉、交互与业务接入分别记录，不能由一个PASS推定其他层次通过。

此工程只验证多系列列表；另外三形态的工程输入及分层记录要求见下节。30系列用于长列表压力测试，不要求生成30种唯一颜色；按HD超25身份规则设计可解释的分组/聚焦或补充编码，检查唯一ID及身份映射稳定，不把自扩色称为正式色板。

## 另外三种布局的工程输入

每例新开对话，只发送对应引用段，不把后面的核对标准当提示输入。需要盲测时由评测者单独保留预期；若让同一Agent读过完整测试文件，仍可检查实现，但需注明非盲测。

### 工程G1：基础单项

> 使用当前测试包生成HD单系列温度折线原型，Vue 3 + TypeScript + ECharts；已有宿主时沿用其工程和门禁。演示数据10:00=23.123456℃、10:10=0℃、10:20=缺失，时间格式HH:mm，数值保留6位。系列名称为“北区测试设备一号温控模块入口温度传感器原始测量值”，采用通用Tooltip基础单项布局和数据项触发。请交付工程、预览与HANDOFF，记录实际验证和未验证项。

核对：时间标题、单行名称与数值/必要单位角色正确；最长名称不被截成无法识别；数值可读、零不变缺失、缺失不造点。检查普通卡片320px上限与260px实际视口的适配；不把同轴多系列列表当成单项工程覆盖。没有数据点的缺失位置不要求伪造命中目标，可用数据表或已解释的交互保留信息。

### 工程G2：单组指标拆解

> 使用当前测试包生成HD设备区间温度图原型，Vue 3 + TypeScript + ECharts；有宿主则按其交付机制。对象A“北区测试设备一号温控模块入口传感器”：最低18.25、最高32.50、平均25.12℃；对象B“南区测试设备二号温控模块入口传感器”：最低21.00、最高35.75、平均缺失。字段直接使用本次演示输入，不重新计算平均。每个对象命中后用通用Tooltip单组拆解，依次展示最低、最高、平均，精度2位。交付工程、预览和HANDOFF。

核对：命中A/B时对象身份及字段一致，首行圆点/对象标题与子指标角色区分；标题后8px、同组行间8px；缺失平均为---，不反推。实际生成区间表达，不能只交一个静态Tooltip卡片冒充图表交互。

### 工程G3：多组对比与长内容

> 使用当前测试包生成HD设备温度对比原型，Vue 3 + TypeScript + ECharts；有宿主则沿用其工程机制。A“北区测试设备一号温控模块入口温度传感器原始测量对象”：最低18.25、最高32.50、平均25.12℃、累计采样1000000000000次；B“南区测试设备二号温控模块入口温度传感器原始测量对象”：最低21.00、最高35.75、平均缺失、累计采样2000000000000次。全部为演示数据，两个对象同属本次10:00—11:00采样区间，不计算或补造字段。需要同区间横向查看对应指标，采用通用Tooltip多组对比拆解。请交付工程、预览和HANDOFF，并记录窄视口、长名称及数值的实际情况。

核对：同一对应区间、A/B两列、两侧相同指标顺序与正确单位；1px #F3F3F3分隔线，左右各16px；多列卡片宽度不超过480px且不强制撑满。长名称/长数值换行可读，缺失---。在260px实际视口检查宽度收缩及可访问的溢出内容，不裁掉对象B或末行，不把单列列表通过外推成多列通过。

## 生命周期、实际尺寸与外围HD回归

在G4或适用布局工程中检查以下行为，具体采用何种监听/渲染技术由实现决定：

| 检查 | 可观察结果 |
| --- | --- |
| 跨4px间隙并移入卡片 | 不按鼠标键的实际指针移动可到达；进入后位置稳定，滚轮能滚到末行；拖动采样与自由移动分别记录 |
| 卡片内部滚动 | 不被页面capture或其他全局监听误关闭；滚后Tooltip仍可见且目标不变 |
| 页面/宿主滚动及弹窗 | 外部位置变化后按实际坐标重定位或关闭，无漂移残影；嵌套滚动或弹窗未测试则单列未验证 |
| 全隐藏、筛选无匹配、恢复 | 无可见系列时不残留旧目标卡；恢复后内容与身份正确 |
| 双实例与卸载 | A/B各自提示与状态隔离；卸载后没有旧卡片、监听或延迟回调影响另一个实例 |
| 窄视口 | 记录window实际innerWidth/innerHeight、宿主宽度和卡片边界；要求260px却只能达到266px时，260项未验证，266结果另列 |
| 图例容量 | 测量名称、标记与翻页器实际占用，容器/字体/内容改变时更新；不以硬编码每页3项替代测量（测量结果可以恰好为3项），不靠换行或缩小既定间距代替分页；翻页不改变数据可见性 |
| 颜色范围 | 30系列是Tooltip压力测试；验证唯一ID和稳定映射，不要求30种唯一规范色；扩展色或其他编码为案例处理时如实记录外层HD覆盖范围 |

以上回归用于本次组件专项，不要求每次日常图表生成都执行四形态及所有宿主场景。
